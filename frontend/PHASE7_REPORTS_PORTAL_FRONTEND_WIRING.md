# Frontend API Wiring — Phase 7 (Reports + Retailer Portal)

## Implemented report pages

### Reports wired
- Daily Purchase Report
  - `GET /reports/daily-purchase`
- Daily Dispatch Report
  - `GET /reports/daily-dispatch`
- Collection Report
  - `GET /reports/collection`
- Outstanding Report
  - `GET /reports/outstanding`
- Monthly Business Summary
  - `GET /reports/monthly-business-summary`

### Report UI coverage
- filter by date/date range where relevant
- KPI cards for summary values
- report tables for procurement, dispatch, collections, and outstanding data
- monthly summary grid/table for owner-level visibility

## Implemented retailer portal pages

### Retailer dashboard
- `GET /dashboard/retailer`
- shows latest order, recent invoices, and outstanding summary

### Retailer orders
- `GET /my/orders`
- `GET /my/orders/:id`
- `POST /my/orders/:id/repeat`
- supports visibility of both self-created and office-created orders

### Retailer invoices
- `GET /my/invoices`
- `GET /my/invoices/:id`
- supports visibility of office-generated invoices as well

### Retailer dues
- `GET /my/dues`

### Retailer profile
- `GET /auth/me`
- `GET /retailers/:id`
- `GET /retailers/:id/ledger-summary`

## Important business-specific support
This phase preserves your most important retailer rule:
- orders created by admin on behalf of retailer still appear in retailer portal
- invoices generated by admin still appear in retailer portal
- dues remain attached to the same retailer account
